# 6F 实验：原版外壳只改 `1e9`（不做反混淆/清洗）

日期：2026-10-20 · 执行：6F(kangkang) · 依据：2K 报告的"4 处 1e9 空转"

## 做法

把原版外壳两文件里 `1e9` 全部替换为 `0`（各 4 处，共 8 处），其余字节不动：

| 文件 | 1e9 处数 | 替换后 |
|---|---|---|
| `src/chunks/bundle.fb6e5.js` | 4 | 0 |
| `assets/other/index.ad23f.js` | 4 | 0 |

注意：文件里的 `0x10000000000000000` 含子串 `1000000000`，**不能替换**，本次未动。

## 结果（三个判据）

| 判据 | 结果 |
|---|---|
| `GET /`（页面加载次数） | **1**（无 reload） |
| 主线程可响应（`Runtime.evaluate` 8s 超时） | **是**（4 ms 返回 2） |
| `System.entries()` 里有 `chunks:///WASM-*` | **未取到**（心跳/探针从未触发；外壳解码已崩） |

## 关键负面结果

未捕获异常从 **3 → 114**，首个为：

```
TypeError: h2eSW.Z4_(...)[156] is not a function
  at bundle.fb6e5.js:1:56578
```

## 根因判断

这 4 处 `1e9` **不是空转惩罚，是字符串表/解码表的构建循环上界**：

```js
case 8: f5o = 1e9; F3U = f5o;     // 上界
case 7: m4j = f1z < F3U ? 3 : 6;  // 循环
case 3: h9m(v0S, L2n);            // 逐项写表
```

真实终止条件是迭代变量 `f1z` 到达 `L2n`（表长度），`1e9` 只是"极大上界"。
改成 `0` → 循环一次都不跑 → 表没建 → 解码函数 `h2eSW.Z4_(...)[156]` 取到 undefined。

## 结论

**这条路在 6F 上不成立**，已回滚为原版外壳。
若 2K/7K 那边改完确实推进到 60%，需要确认他们改的是不是同一类循环
（可能他们的 `while(x<1e9) x++` 是真空转，而 6F 的这 4 处是查表循环）。
